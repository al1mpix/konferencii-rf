# Краткая шпаргалка для защиты

## Как представить работу

«Я разработал портал “Конференции.РФ” для бронирования помещений под конференции. В интерфейсе есть приветственная страница, регистрация, авторизация, создание заявки, личный кабинет пользователя и панель администратора. Макеты рассчитаны на настольные и мобильные экраны».

## Возможные вопросы и короткие ответы

**1. Какие таблицы используются в БД?**  
`users` хранит учётные записи и контактные данные. `bookings` хранит заявки: пользователя, помещение, дату, способ оплаты, статус и отзыв. Связь один-ко-многим: один пользователь может иметь несколько заявок.

**2. Почему пароль хранится не обычным текстом?**  
В базе сохраняется хеш пароля через `generate_password_hash`, а при входе пароль проверяется функцией `check_password_hash`.

**3. Как проходит сценарий пользователя?**  
Пользователь регистрируется, входит в систему, выбирает помещение, дату и оплату, отправляет заявку. Заявка появляется в личном кабинете со статусом «Новая».

**4. Что может администратор?**  
Войти с заданными демонстрационными данными, увидеть все заявки, искать их по ФИО/логину/помещению, фильтровать по статусу и менять статус на «Новая», «Мероприятие назначено» или «Завершено».

**5. Когда доступен отзыв?**  
Только когда заявка имеет статус «Завершено». Это проверяется на сервере при отправке отзыва.

**6. Как проверяются данные регистрации?**  
Логин — латиница и цифры, минимум 6 символов; пароль — минимум 8; ФИО — кириллица и пробелы; телефон — `8(XXX)XXX-XX-XX`; email — проверка формата. Уникальность логина обеспечивается ограничением `UNIQUE` в БД.

**7. Как обеспечена адаптивность?**  
В CSS есть медиазапросы для ширины до 850, 600 и 520 px. На узких экранах колонки перестраиваются в одну, формы и кнопки занимают доступную ширину, а карточки располагаются вертикально.

**8. Какие технологии использованы?**  
Python и Flask для серверной логики, SQLite для базы данных, HTML для страниц, CSS для оформления и адаптивности, JavaScript для небольших интерактивных улучшений.

**9. Что изображено на ER-диаграмме?**  
Две сущности — `users` и `bookings`. Поле `bookings.user_id` ссылается на `users.id` и связывает заявку с владельцем.

**10. Что улучшить для реального запуска?**  
Задать секретный ключ через переменную окружения, отключить `debug`, добавить CSRF-защиту, укрепить конфигурацию администратора и подготовить автоматические тесты.

## Быстрый сценарий демонстрации

1. Запустить `python app.py` и открыть `http://127.0.0.1:5000`.
2. Создать обычного пользователя.
3. Войти, создать заявку, показать её в личном кабинете.
4. Выйти и войти администратором: `Conf2027` / `Demo77`.
5. Найти заявку и изменить статус на «Мероприятие назначено», затем «Завершено».
6. Войти обычным пользователем и показать, что для завершённой заявки доступен отзыв.

Демонстрационный логин администратора и режим отладки предназначены только для локального учебного запуска.
