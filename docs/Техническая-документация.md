# Техническая документация проекта «Конференции.РФ»

## 1. Назначение системы

«Конференции.РФ» — учебное веб-приложение для подачи заявок на бронирование помещений под конференции. Пользователь регистрируется, входит в систему, выбирает помещение, дату мероприятия и способ оплаты. Заявку рассматривает администратор, который меняет её статус. После завершения мероприятия пользователь может оставить отзыв.

## 2. Технологии

- Python 3.10 или новее.
- Flask — HTTP-маршруты, обработка форм и серверная логика.
- SQLite — локальная база данных.
- Jinja2 — рендеринг HTML-шаблонов.
- HTML и CSS — структура и адаптивное оформление страниц.
- JavaScript — небольшие клиентские улучшения форм.
- Werkzeug — безопасное хеширование и проверка паролей.

## 3. Основные страницы и маршруты

| Маршрут | Назначение |
|---|---|
| `/` | Приветственная страница |
| `/register` | Регистрация пользователя |
| `/login` | Авторизация пользователя и администратора |
| `/logout` | Завершение сессии |
| `/dashboard` | Личный кабинет и список своих заявок |
| `/booking` | Создание заявки |
| `/review/<id>` | Добавление отзыва к завершённой заявке |
| `/admin` | Панель администратора, поиск, фильтр и смена статусов |

## 4. Проверка данных

При регистрации все поля обязательны. Логин должен содержать латинские буквы и цифры и быть длиной не менее 6 символов. Пароль должен быть длиной не менее 8 символов. ФИО принимает кириллицу и пробелы. Телефон должен соответствовать формату `8(XXX)XXX-XX-XX`. Email проверяется на базовый формат адреса. Уникальность логина также ограничена в SQLite.

Заявка может содержать одно из помещений: «Аудитория», «Коворкинг» или «Кинозал». Способ оплаты: «При очном посещении» или «Перевод по СБП». Дата не может быть в прошлом. Новая заявка получает статус «Новая».

Оставить отзыв можно только для заявки, которая принадлежит текущему пользователю и имеет статус «Завершено». Максимальная длина отзыва — 1000 символов.

## 5. Структура базы данных

### Таблица `users`

| Поле | Назначение |
|---|---|
| `id` | Первичный ключ |
| `login` | Уникальный логин |
| `password_hash` | Хеш пароля |
| `full_name` | ФИО |
| `phone` | Телефон |
| `email` | Электронная почта |
| `created_at` | Дата создания записи |

### Таблица `bookings`

| Поле | Назначение |
|---|---|
| `id` | Первичный ключ |
| `user_id` | Внешний ключ на `users.id` |
| `room` | Тип помещения |
| `event_date` | Желаемая дата конференции |
| `payment` | Способ оплаты |
| `status` | Текущий статус заявки |
| `review` | Отзыв пользователя, если есть |
| `created_at` | Дата создания записи |

Связь между таблицами — один ко многим: одна запись пользователя может быть связана с несколькими заявками. ER-диаграмма находится в `docs/ERD.svg`.

## 6. Статусы заявок

Допустимые статусы: «Новая», «Мероприятие назначено», «Завершено». Администратор может искать заявки по ФИО, логину и помещению, фильтровать по статусу и выбирать новый статус.

## 7. Запуск локально

Для Windows:

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

Для macOS/Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

После запуска откройте `http://127.0.0.1:5000`. База `conference.db` создаётся при первом запуске.

Демонстрационные данные администратора для локальной проверки: логин `Conf2027`, пароль `Demo77`.

## 8. Ограничения и безопасность

Проект рассчитан на учебный локальный запуск. Перед реальным публичным развёртыванием следует задать уникальный `SECRET_KEY` через переменную окружения, отключить режим отладки, добавить CSRF-защиту и хранить административные учётные данные в защищённой конфигурации. Демонстрационные учётные данные не предназначены для реального сервиса.
